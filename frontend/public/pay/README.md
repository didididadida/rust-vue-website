# pay/ —— 联系与打赏码图

站点首页「联系方式」下方的三个码图入口。点击后以弹层展示原图。

| 文件 | 用途 | 来源 |
|---|---|---|
| `wechat-id.jpg` | 微信号二维码 | 项目根 `微信号.jpg`（2026-11-17 归位并改英文名） |
| `wechat-pay.jpg` | 微信收款码 | 项目根 `微信收款码.jpg` |
| `reward.jpg` | 赞赏码 | 项目根 `赞赏码.jpg` |

## 为什么放在 `frontend/public/pay/` 而不是 `static/uploads/`

- `static/uploads/` 是**后端图床目录**：由 Rust 服务提供，受 `deploy.sh` 与数据库归属表管辖，
  是「用户上传的内容」。
- `public/` 下的文件由 Vite 原样复制到站点根，属于**站点自有静态资源**，不经过后端。
- 两者职责不同，混放会让「谁拥有这份文件」变得含糊——这正是层级纪律里
  「一个东西只能有一个位置」要避免的。

## 为什么改用英文文件名

URL 里出现中文需要百分号编码（`%E5%BE%AE%E4%BF%A1...`），复制分享和排查日志时都容易出错。
文件名不代表内容差异时，用可读的英文更稳。

## 更换码图

直接替换同名文件即可，无需改代码。替换后需要重新 `npm run build` 并部署，
因为 `dist/` 是构建产物（`public/` 不参与热更新）。
