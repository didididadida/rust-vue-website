# 部署与运维

> 面向日常维护：怎么部署、怎么排查、日常改内容。
> 项目整体介绍见 [README.md](README.md)，内容文件格式见 [data/README.md](data/README.md)。

本文档中的 `your-server-ip`、`your-domain.com`、`/path/to/wanle` 均为占位符，请替换为实际值。

---

## 一、部署架构

```
用户浏览器
    │  HTTPS :443
    ▼
  Nginx
    ├── /                  → 静态文件（frontend/dist）
    ├── /api/              → 反代到 127.0.0.1:8000
    └── /static/           → 反代到 127.0.0.1:8000
                                │
                                ▼
                        wanle-backend（systemd）
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
                 posts/      data/      static/uploads/
               (.md 文章)  (评论/用户)   (上传的图)
```

**关键点**：后端只监听 `127.0.0.1:8000`，不直接对外，所有外部流量都经 Nginx。

## 二、首次部署

### 2.1 服务器要求

| 项 | 最低配置 | 说明 |
|---|---|---|
| 系统 | Linux（Debian/Ubuntu/CentOS 均可） | 需 systemd |
| 内存 | 512 MB | 编译建议 2 GB |
| 磁盘 | 5 GB | 主要是 Rust 编译产物 |
| 软件 | Rust 1.85+、Nginx | 前端构建需要 Node.js 18+ |

### 2.2 拉取代码

```bash
cd /path/to
git clone https://github.com/<你的用户名>/rust-vue-website.git wanle
cd wanle
cp .env.example .env
```

编辑 `.env`，**至少设置**：

```bash
JWT_SECRET=<随机长字符串>
ADMIN_PASSWORD=<管理员密码>
```

生成随机密钥：

```bash
openssl rand -hex 32
```

### 2.3 构建

```bash
# 后端
cd backend-rust
cargo build --release
# 产物：target/release/wanle-backend

# 前端
cd ../frontend
npm install
npm run build
# 产物：dist/
```

### 2.4 配置 systemd

仓库提供 `deploy/wanle-backend.service` 作为模板，修改其中的路径后安装：

```bash
sudo cp deploy/wanle-backend.service /etc/systemd/system/
# 编辑：把 WorkingDirectory 和 ExecStart 里的路径改成你的实际路径
sudo nano /etc/systemd/system/wanle-backend.service
sudo systemctl daemon-reload
sudo systemctl enable --now wanle-backend
```

> **注意**：`WorkingDirectory` 必须是 `backend-rust/` 目录，
> 因为 `paths::root()` 默认取 `..` 作为内容根目录。
> 若在项目根目录启动，内容目录会指到项目外面，表现为「文章全没了」。

检查：

```bash
systemctl status wanle-backend
curl -s http://127.0.0.1:8000/api/health
```

### 2.5 配置 Nginx

```bash
# 把前端产物放到 Nginx 静态目录
sudo mkdir -p /usr/share/nginx/html
sudo cp -r frontend/dist/. /usr/share/nginx/html/

# 站点配置（参考仓库 nginx/nginx.conf）
sudo cp nginx/nginx.conf /etc/nginx/conf.d/wanle.conf
# 修改 server_name 为你的域名
sudo nano /etc/nginx/conf.d/wanle.conf

sudo nginx -t && sudo systemctl reload nginx
```

### 2.6 首次登录

访问 `https://your-domain.com/admin`，用 `.env` 里的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。

**如果 `.env` 里没设 `ADMIN_PASSWORD`**，后端会随机生成并打印在启动日志里：

```bash
journalctl -u wanle-backend -n 30 | grep -i admin
```

## 三、日常运维

### 3.1 常用命令

```bash
# 后端状态
systemctl status wanle-backend

# 实时日志
journalctl -u wanle-backend -f

# 最近 100 行
journalctl -u wanle-backend -n 100

# 重启后端（改了后端代码后）
systemctl restart wanle-backend

# 重载 Nginx（改了 nginx 配置后）
nginx -t && systemctl reload nginx

# 健康检查
curl -s http://127.0.0.1:8000/api/health
```

### 3.2 更新代码

```bash
cd /path/to/wanle
git pull

# 后端有改动则重新编译
cd backend-rust && cargo build --release
systemctl restart wanle-backend

# 前端有改动则重新构建并同步
cd ../frontend && npm install && npm run build
cp -r dist/. /usr/share/nginx/html/
systemctl reload nginx
```

**注意**：`frontend/dist` 和 `backend-rust/target` 都在 `.gitignore` 里，
`git pull` 不会更新它们，必须手动重新构建。

### 3.3 修改文章

**方式一：后台编辑**（推荐）

登录 `/admin`，点文章进入全屏编辑器，直接改 Markdown 与 front matter，`Ctrl+S` 保存。

**方式二：直接改文件**

```bash
# 在 posts/ 下新建或编辑 .md 文件
nano /path/to/wanle/posts/my-article.md
```

文件格式：

```markdown
---
title: 文章标题
summary: 摘要，列表页显示
category: blog
tags:
- 标签一
is_published: true
created_at: 2026-01-01T00:00:00Z
---

正文用 Markdown 写。
```

保存后**无需重启**，刷新页面即可看到（后端每次请求都重读文件）。

### 3.4 备份

```bash
cd /path/to/wanle
tar czf ~/wanle-backup-$(date +%Y%m%d).tar.gz \
    posts/ data/ static/uploads/ .env
```

**备份必须包含**：
- `posts/` —— 文章
- `data/` —— 评论、用户表、SQLite
- `static/uploads/` —— 上传的图片
- `.env` —— 密钥与管理员密码

### 3.5 恢复

```bash
systemctl stop wanle-backend
cd /path/to/wanle
tar xzf ~/wanle-backup-20260101.tar.gz
systemctl start wanle-backend
```

## 四、管理员密码

### 4.1 查看

```bash
grep ADMIN_PASSWORD /path/to/wanle/.env
```

如果 `.env` 里是空的（首次启动时随机生成）：

```bash
journalctl -u wanle-backend | grep -i "管理员\|admin" | head -5
```

### 4.2 重置

**方式一：改 `.env`**（需重启）

```bash
nano /path/to/wanle/.env      # 修改 ADMIN_PASSWORD
systemctl restart wanle-backend
```

⚠️ 注意：`ADMIN_PASSWORD` 只在 **users.txt 中没有任何管理员时** 生效。
如果已经有管理员账号，改 `.env` 不会覆盖已有密码。

**方式二：直接改 users.txt**

```bash
# 先删掉旧的管理员行，再重启让后端按 .env 重建
sed -i '/^admin:/d' /path/to/wanle/data/users.txt
systemctl restart wanle-backend
```

**方式三：生成 bcrypt 哈希手动写入**

```bash
python3 -c "import bcrypt; print(bcrypt.hashpw(b'新密码', bcrypt.gensalt(12)).decode())"
# 格式：用户名:哈希:角色
echo 'admin:$2b$12$....:admin' > /path/to/wanle/data/users.txt
systemctl restart wanle-backend
```

## 五、内容管理

### 5.1 目录说明

| 路径 | 内容 | 是否需备份 |
|---|---|---|
| `posts/` | 文章 `.md` 文件 | ✅ 必须 |
| `data/comments/` | 评论 JSON | ✅ 必须 |
| `data/users.txt` | 用户表 | ✅ 必须 |
| `data/profiles/` | 个人资料 | ✅ 必须 |
| `data/wanle.db` | 上传记录（SQLite） | ⚠️ 可重建 |
| `static/uploads/` | 上传的图片 | ✅ 必须 |

### 5.2 评论

每篇文章对应一个 JSON 文件：`data/comments/<slug>.json`。

后台 `/admin` 的「评论管理」可审核与删除。

### 5.3 图片

上传的图片在 `static/uploads/`，通过 `/static/uploads/<文件名>` 访问。

后台 `/admin` → 图床可查看与管理。

## 六、故障排查

### 6.1 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 站点 502 | 后端没启动或崩了 | `systemctl status wanle-backend` 看状态 |
| 站点 403 | Nginx 读不到静态文件 | 检查 `/usr/share/nginx/html` 权限 |
| 文章全没了 | 后端工作目录不对 | `WorkingDirectory` 必须是 `backend-rust/` |
| 登录后立刻掉线 | `JWT_SECRET` 每次重启都变 | 在 `.env` 里固定设置 |
| 上传图片 500 | 目录不可写 | `chmod -R a+rw static/uploads` |
| 邮件验证码收不到 | SMTP 未配置 | 设置 `SMTP_*` 变量，或看日志里的验证码 |

### 6.2 排查命令

```bash
# 后端是否在跑
systemctl is-active wanle-backend

# 端口是否在监听
ss -lntp | grep 8000

# 后端能否直连
curl -s http://127.0.0.1:8000/api/health

# Nginx 反代是否通
curl -s http://127.0.0.1/api/health

# 内容目录是否可读
ls -la /path/to/wanle/posts/ | head

# 后端日志中的错误
journalctl -u wanle-backend -n 50 | grep -i error
```

### 6.3 完整重启

```bash
systemctl restart wanle-backend
nginx -t && systemctl reload nginx
curl -s http://127.0.0.1:8000/api/health
```

## 七、安全建议

| 项 | 建议 |
|---|---|
| 后端监听 | 只绑 `127.0.0.1`，不要 `0.0.0.0`（除非用容器且平台要求）|
| `.env` 权限 | `chmod 600 .env` |
| 管理员密码 | 用强密码，定期更换 |
| HTTPS | 用 Let's Encrypt 免费证书 |
| 备份 | 定期备份到异地，不要只放同一块磁盘 |
| CORS | 默认关闭；只有前端独立部署时才设 `CORS_ORIGINS` |
